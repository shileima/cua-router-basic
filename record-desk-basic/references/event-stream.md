# 录制产物解读（events.jsonl / session.json）

`scripts/event-stream.sh stop`（或 `status`）返回的 JSON 里含 `metadataPath` 与 `eventsPath`。用普通文件工具读盘解析；MCP 不直接回传事件内容。

## 文件角色

| 文件 | 角色 |
|---|---|
| `events.jsonl` | **主证据**。逐行 JSON，一行一个事件，含时序、鼠标/键盘、选中/焦点、窗口 AX 内容。 |
| `session.json` | 仅提供路径与会话时序；`endReason` 标记正常结束或 `recording_controls_cancelled`（取消）。 |

## 事件字段要点

- **应用/窗口归属**：事件通常带 app / window 归属字段，用来判断操作发生在哪个应用的哪个窗口。
- **选中 / 焦点 / 目标**：特别关注 selection、selected text、focused element、鼠标与键盘的 target。当用户问“我在看的内容”时，选中/焦点/目标内容往往是最佳线索，可见的周边 UI 也有参考价值。
- **AX 载荷**：可能是完整树，也可能是 diff。AX diff 用紧凑渲染语法：
  - `~` 表示元素被修改
  - `+` 表示新增元素
  - `-` 表示移除元素

## 敏感信息

不要把录制里的敏感信息写进总结或生成的技能。密码、OTP、API key、身份证/护照、银行卡/账号、以及私人的个人/医疗/法律/HR 细节都按敏感处理；工作流形态需要提及时用**占位符或泛化描述**。

## 解读→生成的思路

1. 把 `events.jsonl` 按时间读一遍，归纳“用户到底想达成什么产出”，并列出**完整的动作时间线**。
2. **默认保留全部结构性动作**（打开/激活应用、地址栏导航、点某按钮、填某字段、保存、校验…），按时间顺序逐个映射成回放步骤；只剔除明确的误操作（误点后立刻撤销、无意义的来回滚动）这类噪声。**不要以「意图归纳」为由合并或跳过步骤**——生成的技能要严格覆盖完整录制链路（对齐 `codex-record-skill` 的做法）。
3. 找出**随场景变化的演示值**（网址、工作流名、收件人、金额、文件名…）→ 抽成技能输入参数并保留录制默认值；动作本身与顺序不变。
4. 决定每步用**连接器/专用工具**还是 **Computer Use**（见 `replay-skill-template.md`）。
